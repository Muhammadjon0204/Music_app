# AURA — Архитектура

Статус: **Phase 6 — локальный аудиодвижок.** Документ описывает принятые
решения и правила. Он обновляется вместе с кодом; если код и документ
расходятся — это ошибка, которую нужно исправить.

## 1. Принцип

Один Flutter-проект, модульная структура по слоям. Отдельные пакеты,
backend и кодогенерация не используются, пока для них нет конкретной причины.

Направление зависимостей — только внутрь:

```
presentation ─┐
              ├─► application ─► domain ─► core
app ──────────┘        ▲
data / audio / integrations ──┘ (реализуют контракты domain)
```

## 2. Структура `lib/`

| Каталог | Назначение | Может зависеть от | Появляется |
|---|---|---|---|
| `core/` | Конфигурация, ошибки, `Result`, логирование, утилиты. **Чистый Dart.** | — | Phase 2 ✅ |
| `domain/` | Сущности (`Track`, `Album`, …) и контракты (`PlaybackController`). **Чистый Dart.** | `core` | Phase 2 ✅ |
| `app/` | Корневой виджет, роутер (`go_router`). | все | Phase 2 ✅, роутер Phase 4 ✅ |
| `application/` | Провайдеры состояния и инфраструктуры (логгер, конфиг, часы). Без UI-тулкита. | `domain`, `core` | Phase 4 ✅ |
| `presentation/` | Дизайн-система ([DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)), оболочка с вкладками, экраны, строки (`l10n/`). | `application`, `domain`, `core` | Phase 3–4 ✅ |
| `audio/` | Реализация `PlaybackController` поверх аудиоплагина (just_audio) и тихий движок. | `domain`, `core` | Phase 6 ✅ |
| `data/` | Реализации контрактов domain. Сейчас только `data/demo/` — **демо-данные**; локальная БД и импорт — Phase 7. | `domain`, `core` | Phase 4 (демо), Phase 7 |
| `integrations/` | Адаптеры онлайн-провайдеров. | `domain`, `core` | Phase 10 |

Пустые каталоги заранее не создаются — каждый появляется на своём этапе.

Правило «`core` и `domain` — чистый Dart» проверяется автоматически:
[test/architecture/layer_dependencies_test.dart](../test/architecture/layer_dependencies_test.dart)
падает, если туда попадёт импорт `flutter`, `riverpod`, `dart:io`, `dart:ui`
или внешнего слоя. Это даёт:
- бизнес-логику, тестируемую без Flutter-окружения;
- независимость от конкретного аудиоплагина и провайдера;
- переносимость на Android без переписывания логики.

## 3. State management — Riverpod 3 (`flutter_riverpod`)

**Выбор:** `flutter_riverpod` 3.4.3 (MIT, verified publisher, активно
поддерживается). Используется **без кодогенерации** (`riverpod_generator` и
`build_runner` не подключаются).

**Почему:**
- Плееру нужен один общий экземпляр состояния, который читают мини-плеер,
  Now Playing и очередь (п. 12.J). Riverpod даёт это без `BuildContext`.
- Встроенное внедрение зависимостей: реализации (`audio/`, `data/`)
  подменяются в тестах через `overrides`, без сторонних DI-библиотек.
- Удобно работает со стримами (позиция трека, состояние плеера).
- Точечные подписки (`select`) — частые обновления прогресса не
  перестраивают весь экран (п. 13).

**Рассмотренные альтернативы:**
- `flutter_bloc` — зрелый, но больше шаблонного кода; DI нужно решать отдельно.
- `provider` — проще, но завязан на `BuildContext` и дерево виджетов.
- `ChangeNotifier`/`ValueNotifier` без библиотеки — придётся вручную
  строить DI и жизненный цикл.

**Важная деталь Riverpod 3:** все провайдеры сравнивают старое и новое
состояние через `==`, чтобы решить, уведомлять ли подписчиков. Поэтому все
классы состояния обязаны иметь корректное value-равенство (см. §5).

**Риски:** транзитивные зависимости (`riverpod`, `state_notifier`, `uuid`,
`crypto`, `fixnum`, `typed_data`, `listen`); привязка к API Riverpod в слоях
`application`/`presentation` (но не в `domain`).

## 4. Доменная модель

- **Типизированные ID** (`TrackId`, `AlbumId`, `ArtistId`, `PlaylistId`,
  `ProviderId`, `ExternalTrackId`) — extension types над `String`.
  Перепутать `TrackId` и ID провайдера — ошибка компиляции.
- **`Track` ≠ источник.** `Track` описывает запись в библиотеке AURA;
  `sources: List<TrackSource>` — откуда её можно воспроизвести:
  - `LocalFileSource(fileReference)` — импортированный файл; ссылка
    непрозрачна для домена, её интерпретирует слой `data`;
  - `ProviderTrackSource(providerId, externalId)` — трек онлайн-провайдера.
    **URL потока не хранится**: он может быть временным или подписанным и
    запрашивается непосредственно перед воспроизведением.
- **Отсутствующие метаданные — `null`**, а не строка «Unknown». Локализованный
  текст («Неизвестный исполнитель») выбирает presentation-слой.
- **`Playlist`** ссылается на треки через `TrackId` — локальные и онлайн-треки
  можно смешивать.
- Инварианты проверяются в конструкторе (пустое название, трек без
  источников, индекс вне очереди) и бросают ошибку всегда, а не только в debug.

## 5. Воспроизведение — единый контракт

`domain/playback/playback_controller.dart` — **единственная точка**, через
которую UI управляет плеером:
- UI читает `snapshot`/`snapshots` и отправляет команды (`play`, `seek`,
  `skipToNext`, …).
- **Позиция — отдельный стрим `positions`**, не входит в `PlaybackSnapshot`:
  тики прогресса не перестраивают весь плеер.
- Ожидаемые ошибки (файл недоступен, формат не поддерживается) публикуются в
  `PlaybackSnapshot.failure`, а не бросаются исключением.
- `PlaybackSnapshot` назван так намеренно, чтобы не конфликтовать с
  `PlayerState`/`PlaybackState` из вероятных аудиопакетов.

Реализации пока **нет** — она появится в `audio/` на Phase 6. Алгоритм
shuffle, редактирование очереди (добавить следующим, перестановка) и
восстановление состояния будут добавлены в контракт на Phase 5–6.

## 6. Обработка ошибок

| Ситуация | Механизм |
|---|---|
| Ожидаемая ошибка (нет файла, нет сети, отказ в разрешении) | `Result<T>` = `Ok` / `Err(AppFailure)` |
| Ошибка программиста (нарушение инварианта) | исключение (`ArgumentError`, `RangeError`) |
| Неперехваченная ошибка | `FlutterError.onError` и `PlatformDispatcher.onError` в `main.dart` → логгер |

`AppFailure` — sealed-иерархия (`FileAccessFailure`, `UnsupportedMediaFailure`,
`PermissionDeniedFailure`, `NetworkFailure`, `StorageFailure`,
`PlaybackFailure`, `UnexpectedFailure`). Presentation-слой выбирает текст
для пользователя через исчерпывающий `switch` по подтипу. Поля
`debugMessage`, `cause`, `stackTrace` — только для разработчика и никогда
не показываются пользователю.

## 7. Логирование

`AppLogger` → `DeveloperLogger` (`dart:developer`, видно в DevTools →
Logging). В release-сборке отключён.

**Запрещено логировать:** токены, API-ключи, подписанные и приватные URL,
содержимое файлов, персональные данные. Вместо значений логируются ID и
количества.

## 8. Конфигурация

`AppConfig` читает `--dart-define=AURA_ENV=development|production`.
Пустое значение → окружение по режиму сборки. Неизвестное значение →
падение при старте (fail fast).

**`--dart-define` компилируется в бинарник и извлекается из него — секреты
так не передаются.** Если провайдеру понадобится секрет, нужен серверный
компонент (п. 11.1); решение будет принято на Phase 9.

## 9. Правила именования и стиль

- Файлы — `snake_case.dart`, один публичный тип (или тесная группа) на файл.
- Импорты — только `package:music_app/...` (lint `always_use_package_imports`).
- Классы домена — `final class`; иерархии — `sealed class`.
- Состояние неизменяемо; списки в моделях — `List.unmodifiable`.
- У классов состояния — value-равенство (`==` и `hashCode`).
- Провайдеры — `<имя>Provider`, рядом с тем, что они предоставляют, вне
  `core`/`domain`.
- Тесты повторяют структуру `lib/`: `test/domain/music/track_test.dart` и т. д.

Анализатор: `flutter_lints` + `strict-casts`, `strict-inference`,
`strict-raw-types`, `avoid_dynamic_calls`, `unawaited_futures`,
`prefer_final_locals`, `prefer_single_quotes`.

## 10. Навигация (Phase 4)

- `go_router` 18.x (официальный пакет flutter.dev, статус «feature-complete»).
  `StatefulShellRoute.indexedStack`: три вкладки — Главная, Поиск,
  Библиотека — каждая со своим стеком экранов; состояние вкладки
  сохраняется при переключении. Повторное нажатие на вкладку возвращает в
  её корень (как в iOS).
- Неизвестный адрес → переход на Главную, а не страница ошибки с
  технической информацией. Deep links на iOS пока не включены; их
  параметры будут валидироваться при включении (Phase 12).
- Каталог компонентов доступен из Главной только в debug-сборке.
- **Важно:** go_router 18 распознаёт только `MaterialApp` из отдельного
  пакета `material_ui`. С `MaterialApp` из самого Flutter он молча
  создаёт страницы **без анимации и без iOS-свайпа назад**. Поэтому все
  маршруты строятся через `_page()` в `app/router.dart` (`MaterialPage`),
  и тема переходов приложения применяется. Проблему поймал стресс-тест;
  её регрессию ловят тесты «iOS edge swipe» и «iOS slide by default».

## 11. Внедрение зависимостей и демо-данные

Реализации подключаются в **composition root** (`main.dart`) через
переопределение провайдеров, например `homeFeedSourceProvider`. Провайдер
без переопределения сразу падает с понятной ошибкой.

**Демо-данные** (`lib/data/demo/`) — вымышленные названия, без обложек,
ID с префиксом `demo-`, `HomeFeed.isDemo = true`. Главная показывает
плашку «Демо-данные». Демо-карточки не нажимаются: за ними ничего нет.
С Phase 7 Главная строится из библиотеки (`LibraryHomeFeedSource`), а
демо-лента показывается, только пока библиотека пуста.

## 11a. Плеер (Phase 5)

- **Логика очереди — в домене**: `domain/playback/playback_queue.dart`
  (`PlaybackQueue`). Хранит исходный порядок и порядок воспроизведения
  (shuffle можно выключить без потери исходного порядка). Правила как в iOS:
  repeat-one повторяет трек только при естественном окончании, «вперёд»
  всё равно переключает; «назад» после 3 секунд перезапускает текущий
  трек. Не зависит от аудиоплагина — переиспользуется движком на Phase 6.
- **Воспроизведение (Phase 6)** — слой `lib/audio/`:
  - `AudioEngine` — тонкий интерфейс над плеером платформы;
  - `JustAudioEngine` — настоящий звук через just_audio (iOS, Android, веб,
    macOS) + `audio_session` с категорией «музыка»;
  - `SimulatedAudioEngine` — **без звука**, по таймеру: для Windows/Linux, где
    у just_audio нет реализации, и для тестов. Интерфейс тогда показывает
    «Без звука» (`isSilentPlaybackProvider`);
  - `EnginePlaybackController` — единственная реализация
    `PlaybackController`: правила очереди из `PlaybackQueue` + движок. У
    каждой загрузки свой номер: результаты устаревших загрузок и устаревшие
    события «трек закончился» игнорируются (быстрые нажатия «вперёд»).
    Ошибка файла показывается пользователю и останавливает воспроизведение;
    технические детали — только в `debugMessage`;
  - `resolveTrackAudio` — выбирает воспроизводимый источник трека
    (встроенный файл, локальный файл); онлайн-источники — с Phase 10.
- **Демо-треки** — 4 тона, синтезированные `tool/generate_demo_tones.dart`
  (12 с, WAV 16 кГц моно, ~1,5 МБ) — сторонних прав нет. Тест проверяет,
  что длительность файлов совпадает с метаданными.
- Прерывания, фон и экран блокировки — см. раздел 11c (Phase 8).
- **Позиция** — отдельный `playbackPositionProvider`: каждую долю секунды
  перестраиваются только полоска прогресса и время, а не весь экран.
- **Экраны**: мини-плеер (в оболочке вкладок) → Now Playing (маршрут
  `/player` поверх вкладок, выезжает снизу, закрывается кнопкой или свайпом
  вниз) → очередь (`/player/queue`). Обложка перелетает между мини-плеером
  и Now Playing (Hero). При Reduce Motion — затухания вместо движения,
  Hero выключен.
- Если плеера нет (`playbackControllerProvider` = `null`), мини-плеер и
  кнопка «Слушать» на баннере не показываются.
- Доменный enum называется `PlaybackRepeatMode`: во Flutter 3.47 появился
  собственный `RepeatMode`, и имена конфликтовали.

## 11b. Локальная библиотека (Phase 7)

- **Импорт** — только то, что пользователь сам выбрал в системном
  выборе файлов (`file_picker`, на iOS — `UIDocumentPicker`, приложение
  «Файлы»). Устройство не сканируется, разрешения в `Info.plist` не нужны.
  Выбранный файл на iOS — временная копия, которую система удаляет,
  поэтому файл **один раз** копируется в контейнер приложения
  (`Application Support/library/audio/<sha256><расширение>`); временные
  копии сразу удаляются (`clearTemporaryFiles`).
- **Дубликаты** — по содержимому (SHA-256 потоково, без чтения файла в
  память целиком): тот же файл под другим именем не добавится второй раз.
  ID трека выводится из хэша (`local-…`).
- **Метаданные** — `audio_metadata_reader` (чистый Dart; MP3/ID3, MP4/M4A,
  FLAC, WAV, AIFF), чтение в отдельном изоляте. Нет тега названия → имя
  файла; нет исполнителя/альбома → `null`, интерфейс пишет «Неизвестный
  исполнитель». Обложка (до 5 МБ, предпочтительно front cover) сохраняется
  в `artwork/<sha256>` — одинаковые обложки альбома хранятся один раз.
  Нечитаемый или неподдерживаемый файл пропускается и попадает в отчёт.
- **Хранение** — `sembast` (NoSQL на чистом Dart, транзакции):
  треки, избранное (с отметкой времени, новые сверху), плейлисты. Пути в
  базе — относительные ссылки `library:audio/…`: на iOS путь к контейнеру
  меняется между запусками/обновлениями. `LibraryPaths.resolve` отклоняет
  `..` и пустые сегменты. Повреждённые записи пропускаются, а не роняют
  приложение. Не открылась база → временная библиотека в памяти и
  предупреждение на экране. На вебе — всегда в памяти (у браузера нет
  постоянного доступа к файлам), импорт скрыт, есть «Добавить демо-треки».
- **Контракт** `LibraryRepository` (`domain/library/`) с двумя
  реализациями (`SembastLibraryRepository`, `InMemoryLibraryRepository`),
  обе проходят один набор контрактных тестов. Наружу — поток неизменяемых
  `LibrarySnapshot`; альбомы и исполнители вычисляются из тегов
  (альбом = название + исполнитель альбома, без учёта регистра и «ё»).
- **Удалённые файлы** — `missingTracksProvider` проверяет наличие копий;
  такой трек подписан «Файл недоступен», пропускается при воспроизведении
  списка и может быть удалён. Удаление трека из библиотеки удаляет и его
  копию (оригинал в «Файлах» не трогается).
- **Экраны** — Библиотека (категории + недавно добавленные), «Вся музыка»
  (сортировка: название / исполнитель / сначала новые), «Любимые треки»,
  альбомы, исполнители, плейлисты (создать, переименовать, удалить, убрать
  трек). Списки, а не сетки — читаются при самом крупном шрифте. Страницы
  альбома, исполнителя и плейлиста открываются **внутри текущей вкладки**
  (`/home/album/…`, `/search/album/…`, `/library/album/…`); ID в адресе
  кодируются. Удалённый объект → «Не найдено», а не ошибка.
- **Поиск** — по библиотеке в памяти: каждое слово запроса должно найтись
  в названии, исполнителе или альбоме (регистр и «ё» не важны).
- **Сердечко** в Now Playing — только для треков из библиотеки.

## 11c. Фон, экран блокировки, прерывания (Phase 8)

- **Фоновое аудио на iOS**: `UIBackgroundModes = audio` в `Info.plist`
  (и только он — другие режимы требуют обоснования для App Store) +
  категория аудиосессии «playback» (`AudioSessionConfiguration.music()`).
  Тест `test/platform/ios_config_test.dart` следит, чтобы настройка не
  пропала.
- **Прерывания** обрабатывает `EnginePlaybackController`, а не just_audio
  (у плеера `handleInterruptions: false`): иначе плагин ставил бы паузу
  «за спиной» контроллера и интерфейс показывал бы «играет». События
  аудиосессии переводятся в `AudioInterruption`
  (`audio/audio_interruptions.dart`):
  - звонок / будильник / другое приложение → пауза; по окончании —
    продолжение, **только если** система разрешила (`shouldResume`) и
    пользователь за это время ничего не нажимал (play, pause, новая
    очередь отменяют автопродолжение);
  - отключение наушников / AirPods → пауза **без** автопродолжения;
  - «приглушение» (Android) → громкость 0,3 и обратно.
- **Системные элементы управления** — `SystemMediaSession`
  (`audio/system_media_session.dart`, обработчик `audio_service`):
  зеркалит `PlaybackController` на экран блокировки, Пункт управления,
  кнопки наушников/AirPods и Media Session браузера; их команды идут в тот
  же контроллер, поэтому приложение и система всегда согласованы. Позиция
  отправляется только при скачке (перемотка, смена трека, пауза) — между
  ними система сама считает её по `updateTime`. Нет тегов → пустые поля,
  а не «Неизвестный исполнитель». Обложка — локальный файл библиотеки.
  «Стоп» от системы только ставит паузу, очередь сохраняется.
- Включено на iOS, macOS и вебе. На Android `audio_service` требует
  изменений в манифесте и `MainActivity` — сделаем вместе с Android-портом.
  Не удалось запустить сервис → приложение играет как раньше, ошибка
  только в логе.

## 11d. Фундамент онлайн-источников (Phase 10)

- **Модель.** Онлайн-трек — `Track` с `ProviderTrackSource` (провайдер +
  внешний ID). ID трека в приложении — `<провайдер>:<внешний id>`
  (`ProviderTrackSource.trackId`): одинаковые ID у разных провайдеров не
  совпадут, с локальными `local-…` — тоже. Источник хранит доступность
  (`StreamAvailability`: unknown / full / previewOnly / externalOnly /
  unavailable — **unknown никогда не считается воспроизводимым**), ссылку
  на оригинал и лицензию. Адрес потока **не хранится**: он может быть
  временным и подписанным, его получают прямо перед воспроизведением.
- **Хранение.** Новые поля — необязательные ключи в той же схеме v1:
  старые записи читаются без миграции (проверено тестом), неизвестные
  значения → `unknown`, сохраняются только http(s)-ссылки.
- **Контракт провайдера** (`domain/providers/music_provider.dart`):
  `MusicProvider` (id, имя) + отдельные возможности
  `SearchableProvider`, `PopularTracksProvider`, `TrackDetailsProvider`,
  `StreamingProvider`. Провайдер реализует только то, что умеет;
  `ProviderRegistry.capability<T>()` сообщает об отсутствии функции как
  `FeatureUnavailableFailure`. Локальной музыке реестр не нужен.
- **Разрешение аудио асинхронное** (`TrackAudioResolver`): локальные
  источники — как раньше, онлайн — через `StreamingProvider.streamUri`
  (только HTTPS) → `StreamAudio`; just_audio сам следует за редиректом
  на подписанный URL. У каждой загрузки свой `Cancellation`: при смене
  трека сетевой запрос старого отменяется, а его результат игнорируется.
- **Состояния плеера подтверждает движок.** `PlaybackStatus`: idle,
  loading (разрешение/открытие), buffering (ждём данных), playing (движок
  сообщает playing + ready), paused, completed, failed. Отдельно —
  `playWhenReady` (намерение пользователя): кнопки play/pause следуют ему,
  и пока идёт загрузка или буферизация, на кнопке крутится индикатор.
- **Ошибки во время воспроизведения** приходят из `AudioEngine.errors`
  (just_audio `errorStream`) и переводят трек в failed. Коды платформ
  переводятся в причину (`classifyAudioError`) только по документированным
  значениям; неизвестное остаётся общей `PlaybackFailure`, а не догадкой.
  **Автоповторов нет**: «play» после ошибки — одна новая попытка с того же
  места (адрес потока получается заново), «next» — следующий трек.
- **Ошибки** (`AppFailure`): добавлены Timeout, Server, RateLimited,
  NotFound, AccessDenied, InvalidResponse, FeatureUnavailable, Cancelled —
  у каждой свой понятный текст, технические детали только в логах.
- **HTTP** (`data/network/json_http_client.dart`, пакет `http`):
  тайм-аут с реальным прерыванием запроса, отмена, типизированные статусы,
  проверка JSON и размера ответа, не больше 2 попыток и только для
  тайм-аутов и 502–504 (429 и 4xx не повторяются). В логах — только хост
  и путь, без query.
- **Android:** разрешение INTERNET добавлено в основной манифест (раньше
  было только в debug/profile).

## 11e. Audius (Phase 11)

- **Источник:** официальный публичный REST API `https://api.audius.co/v1`
  (`data/providers/audius/`). Только чтение, без ключа и секретов: запросы
  подписаны публичным параметром `app_name=AURA`, как разрешает
  документация. Бесплатный план — 10 запросов/с, 500 тыс. в месяц;
  приложение делает несколько запросов на экран.
- **Условия API (ApiTerms.pdf, §2):** разрешено **только кэширование в
  пределах сессии**. Поэтому метаданные и обложки Audius хранятся только в
  памяти (Riverpod-провайдер на сессию, `ImageCache`), на диск ничего не
  пишется. Скрейпинг запрещён — используется только официальный API.
- **Возможности:** поиск (`/tracks/search`), популярное
  (`/tracks/trending`), подробности (`/tracks/{id}`), поток
  (`/tracks/{id}/stream` — редирект на короткоживущий подписанный URL,
  по которому just_audio идёт сам; подписанный `stream.url` из ответов
  игнорируется и никогда не хранится).
- **Доступность** — из флагов API: `access.stream` → полный трек;
  `stream_conditions` (подписка/покупка на Audius) → «Только в Audius»
  (открывается ссылкой); удалён / недоступен / аккаунт отключён /
  `is_streamable=false` → недоступен и в списки не попадает.
- **Обложки:** Audius хранит их на нескольких узлах, и отдельный узел
  может не отвечать (проверено: 404 у части треков). По их руководству
  «Image Loading & Mirrors» трек хранит запасные адреса
  (`Track.artworkAlternatives`), а `FallbackNetworkImage` пробует их по
  очереди; при полном провале — градиентная заглушка.
- **Экраны:** на Главной «Популярное в Audius» (при пустой библиотеке —
  вместо демо-ленты, плюс карточка «Добавьте свою музыку»); в Поиске —
  секция Audius под результатами библиотеки, со своими загрузкой, ошибкой
  и «Повторить», кнопкой «Показать ещё»; устаревший запрос отменяется
  при новом вводе; ошибки одного источника не скрывают другие. В плеере —
  «Источник: Audius ↗» со ссылкой на страницу трека (`url_launcher`,
  только https). Треки, которые нельзя играть в AURA, в очередь не
  попадают — открываются на Audius.
- **Демо-лента Главной** больше не подключается: её место занял настоящий
  каталог. Демо-тоны остаются кнопкой «Добавить демо-треки» в Библиотеке.

## 11f. Надёжность плеера и очередь (Phase 12)

- **Редактирование очереди** — в домене (`PlaybackQueue`): «Играть
  следующим» (`insertNext`), «В конец очереди» (`append`), удаление
  (`removeAt`), перестановка (`move`). Работает и при включённом shuffle:
  без перемешивания меняется исходный порядок, с перемешиванием — только
  порядок воспроизведения, так что выключение shuffle ничего не теряет.
  Текущий трек при этом продолжает играть; его самого из очереди не
  убрать (его пропускают кнопкой «Далее»).
- **Экран очереди**: перестановка за «ручку», кнопка удаления у каждого
  трека; для VoiceOver у ручки есть действия «Переместить выше/ниже».
  В меню трека (библиотека и Audius) — «Играть следующим» и «В конец
  очереди».
- **Старт без мигания**: `setQueue(..., play: true)` сразу помечает
  намерение играть — на кнопке не появляется «play» на долю секунды.
- **Мёртвые треки**: если очередь переходит дальше сама (трек доиграл),
  трек, который здесь не может играть (удалён, закрыт, формат), пропускается
  — не больше `maxAutoSkips` = 5 подряд. Проблемы сети (нет связи,
  тайм-аут, лимит, сбой сервера) **не** пропускаются: следующий трек упал
  бы так же, а очередь молча опустела бы. Трек, выбранный пользователем,
  не пропускается — о нём сообщается.
- **Перемотка во время загрузки** запоминается и применяется, как только
  трек откроется.
- **После ошибки** в «Сейчас играет» видны причина, пояснение и кнопка
  «Повторить» (одна попытка с того же места); автоповторов нет.

## 13. Что сознательно НЕ сделано

  выделения.
